Emergency communication: which transport is actually realistic?

You asked whether AlertAble should use a dedicated emergency line or messaging over 2G/Wi-Fi. The defensible answer is neither in isolation — it is a cascading transport ladder that degrades gracefully as infrastructure fails.

Recommendation

Why a “dedicated line” is not something an app can provision

A genuinely dedicated emergency channel means reserved spectrum or network priority — the model behind FirstNet in the US or Priority Telecommunications Service. That is granted by telecom regulators and carriers, not implemented in application code. For a capstone, claiming a dedicated line would be a claim you cannot demonstrate. What is achievable is an institutional dedicated line: registering AlertAble with the barangay/LGU DRRM office so the Responder Dashboard becomes the official intake channel. The line is organisational; the transport underneath it is tiered and technical.

Recommended: four-tier cascading transport

TierTransportWhen it is usedRealistic implementation
T1 IP data
Wi-Fi / LTE / 5G		 Normal conditions. Full feature set — live tracking, maps, photos, dashboard sync. REST over HTTPS (TLS 1.3) to Node.js; MQTT or WebSocket for live telemetry. MQTT preferred — ~2 byte header vs HTTP's ~700, so it survives degraded bandwidth far better.
T2 SMS over 2G/GSM Data network congested or unavailable but towers still standing — the most common real disaster condition. 2G needs far less signal strength than LTE and is store-and-forward, so messages queue instead of failing. Send compact GSM-7 encoded status codes (not free text) through a PH-local SMS gateway — Semaphore, Movider, or Globe Labs — with delivery receipts. A full SOS fits in a single 160-char segment.
T3 Offline P2P mesh Total blackout — towers down, no cellular at all. Google Nearby Connections API in P2P_CLUSTER strategy over BLE + Wi-Fi Direct, multi-hop with TTL counter and UUID dedup. Carries structured packets only, never media.
T0
(inbound)		 ECBS cell broadcast Always — receive-only official government alerts. 3GPP Cell Broadcast Service. Requires no registration, no data, no SIM credit. AlertAble cannot send on this channel, only listen and enrich the alert with the user's mobility profile.

Why this is the stronger answer for a panel: it does not overclaim. It acknowledges that each transport fails under different conditions, and shows that the system is designed to detect which tier is available and fall back automatically — which is exactly the resilience argument your problem statement is built on.

One caveat to be upfront about: SMS costs money per message and depends on a gateway contract, so a real deployment would need either LGU sponsorship or a telco partnership — the same institutional dependency as the “dedicated line” idea, just far more achievable.

About DND override

Emergency alerts will sound and vibrate even if your phone is silenced. Only official hazard alerts use this — never app updates or messages.

Technologies
  • Android: NotificationChannel with IMPORTANCE_HIGH + setBypassDnd(true), gated behind the ACCESS_NOTIFICATION_POLICY permission (user grants it in system settings, app cannot self-grant)
  • Audio routing: AudioAttributes.USAGE_ALARM + CATEGORY_ALARM so playback uses the alarm stream, which ignores ringer volume
  • iOS: UNNotificationInterruptionLevel.critical — requires Apple's Critical Alerts entitlement, which must be applied for and justified. Worth flagging as a real deployment dependency, not an assumption
  • Location: ACCESS_FINE_LOCATION + FOREGROUND_SERVICE_LOCATION; background access requested only at first real alert, not at signup
